# AI Programming Foundations Project

This project builds a complete, reproducible exploratory data workflow for the
[Titanic training dataset](https://www.kaggle.com/c/titanic/data). The notebook
loads the raw passenger records, audits data quality, applies documented cleaning
functions, summarizes key groups, creates three labeled visualizations, and records
the analysis assumptions and limitations.

## What I Built

- `data_workflow.ipynb`: executable ingestion, cleaning, EDA, visualization, and
  interpretation workflow.
- `data/titanic.csv`: the 891-row source dataset used by the notebook.
- `figures/`: three figures generated by the executed notebook.
- `module_summary.pdf`: written report with academic citations and references.
- `requirements.txt`: pinned dependencies captured from the working environment.

## How to Run

1. Clone the repository and enter its directory.
2. Create and activate a Python 3.9+ virtual environment.
3. Install the dependencies:

   ```bash
   pip install -r requirements.txt
   ```

4. Start Jupyter:

   ```bash
   jupyter notebook
   ```

5. Open `data_workflow.ipynb` and choose **Run All**. Run the notebook from the
   repository root so the relative path `data/titanic.csv` resolves correctly.

## Reproducibility

The notebook uses relative paths, performs cleaning on a copy of the raw data, sets
a fixed random seed, includes explicit validation assertions, and saves every figure
to `figures/`. Dependency versions were captured with `pip freeze` and reduced to the
packages used by this project. Git history records the project in separate scaffold,
analysis, and reporting stages, with development performed on an additional branch.

## Bias Awareness

Dropping all incomplete records would disproportionately remove passengers with
missing ages or cabins and could distort class-related patterns. The workflow keeps
missingness indicators, imputes age within sex and passenger class, avoids fabricating
cabin values, and reports small-group counts alongside rates. These historical,
observational records support descriptive association only; the notebook does not
make causal claims or treat sex, class, or survival outcomes as normative judgments.

## Future Integration Reflections

### Machine-learning workflow changes

A predictive extension would split train and test data before learning preprocessing,
fit categorical encoders and imputers inside a pipeline, prevent target leakage, and
report performance by sex and passenger class in addition to aggregate metrics.

### Neural-network preparation

Neural-network input would require numeric tensors, scaled continuous features, and
carefully encoded categorical features. A separate validation set, regularization,
and calibration checks would be necessary because this dataset is small and uneven
across demographic and class groups.

### Agentic automation potential

An agent could automate schema checks, run the notebook, compare data-quality metrics
with prior runs, and flag failed assertions. Human review should remain responsible for
source selection, interpretation, citation accuracy, and decisions that could amplify
historical bias.
